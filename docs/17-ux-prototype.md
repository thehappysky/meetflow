# 日常页面原型与待确认问题

## 交付范围

此次用可点击页面验证 docs/16-product-requirements.md 的主要路径。原型为示例状态模拟，存放于 design/prototypes；不接入业务系统，不修改现有数据，角色切换不是真实权限。

### 销售的主要操作

| 目的 | 页面入口 | 用户做什么 | 系统/原型展示什么 |
|---|---|---|---|
| 录入会谈 | 会谈录音 | 直接拖入或选择文件；可不填标题 | 按上传时段命名，整理并自动保存；未上报仅自己可见 |
| 复盘 | 会谈详情 | 点纪要/后续事项/复盘建议 | 重点、来源、待确认日期；无需手动再保存纪要 |
| 生成周报 | 工作简报 | 核对正文，集中补日期或保留未知，确认一次 | 来源映射与时间待确认单列，Word/PDF 同版本预览 |
| 进入中心 | 录音列表勾选 | 查看本次范围并确认上报 | 未选记录保持个人可见，中心固定上报版本 |
| 更正中心 | 已上报 → 申请更正 | 提交修改和原因 | 主管确认后中心新版本，个人区不会暗中覆盖中心 |

原型中上报前补客户/商机是临时假设，已向用户提问。不能将这个原型状态当成已确认要求。正式日常界面不出现模型/Agent/评分卡版本选择；演示按钮、身份选择和示例说明是原型专用标识。

### 主管与老板

- 主管：“团队关注”看已上报客户的推进与待协助项；“更正申请”核对差异并确认新版。
- 老板：“公司简报”看已上报范围的变化及公司级资源事项，可以进入中心原会谈。
- 个人录音删除后不影响中心；老板和主管界面不展示未上报录音。

## 此次浏览器验证

使用用户本地 Chrome，未使用内置浏览器。逐项测试示例上传、日期未知不阻塞周报、确认后的 Word/PDF 预览、上报、更正申请、主管新版、删除个人仍保留中心及老板范围。

检查 390px 首页和 320px 报告/主管/老板的根元素可见宽度与滚动宽度一致，未出现横向溢出，临时尺寸已恢复。主场景没有捕获到浏览器脚本错误。截图在 test-results/ux-prototype/sales-home.jpg。

这不等于正式应用测试，也不证明真实 ASR、导出文件和权限已经实现。源脚本有语法检查；没有为纯原型重新运行无关业务测试。

## 仍需用户决定的两项

1. 账号由老板/管理员统一建立并分配团队，还是邀请码自行注册。已提供前者作为建议。
2. 客户/商机未知的录音，上报前要求补选，还是可先作为待归属进入中心。上传始终不受这个条件限制。

## 可以先给默认设计、无需现在逐项追问的内容

- 模板先提供企业服务销售周报示例，后台管理配置一次，销售日常复用；正式输出仍按已确认 Word/PDF。
- 个人区修改/删除、中心版本、更正前后对比，按用户已确认边界落实。
- 用明确的“日期待确认”“尚无完成记录”等文案，不把未知显示为失误或逾期。
- 重试/错误状态保留已完成内容，正式接口幂等；原型当前仅演示成功路径与少量边界。

中心删除保留期、成员转组、特殊共享、导出范围等，在进入相应正式功能实现前再列成具体场景；不让用户现在一次回答全部底层细节。

下一步以本原型的可操作反馈调整方案，再实施真实账号/团队、共用会谈与个人/中心生命周期、报告导出和主要页面；不把示例交互作为成品。
