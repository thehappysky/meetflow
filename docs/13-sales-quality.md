# 方案 A：销售会话质检与辅导（实施契约）

目标用户是已有销售流程与录音/转写的销售主管。保留会议模块；销售工作台按项目隔离。首版是本地单用户试用版，不代表多人生产服务。

## 数据流与验收

发布不可变的阶段评分卡 → 导入会话（销售、客户、实际时间、完整性、逐段身份）→ 冻结会话与规则 → 三路专业分析 → 独立审查/最多一次定向返工 → 代码计算得分与覆盖率 → 主管复核 → 可选本地辅导任务 → 团队汇总与 Markdown 导出。

- 评分卡包含阶段、维度、权重、适用条件、达标/部分达标描述、产品依据；修改发布为新版本，旧分析不改变。
- 会话段落身份为销售/客户/未知；未知身份和不完整材料不得推断为销售未执行。
- 状态为达标/部分达标/未达标/不适用/无法判断。代码按满分/半分/零分计算，仅可评项进入分母，另展示可评覆盖率，不能把未知当零分或把缺项掩盖为满分。
- 三个专家负责需求与交易信息、流程与下一步、产品与承诺；审查者可以指出具体规则问题，定向返工一次，剩余争议转无法判断。
- 工具只读冻结快照与上游产物；每次调用前持久预留累计预算。SQLite 检查点与已完成产物支持失败恢复。真实模式无配置/失败均不转演示。
- 规则演示采用可见的字面命中词，未知默认保留，不模拟真实语义能力。真实模型接入沿用工具调用适配器，实际质量需要用户配置后验证。
- 人工复核绑定报告 hash 与会话版本，幂等保存；覆盖机器判断必须填写原因。辅导任务只在显式选择后写入现有本地看板。
- 汇总仅计已复核记录；按模式、阶段、评分卡版本和销售人员筛选。展示样本数、覆盖率、规则问题和客户信号；不生成成交率、收入或没有 CRM 依据的因果结论。
- 音频需要已有 ASR 配置。转写后先逐段确认身份，才进入评价；无自动说话人分离。文字输入支持“销售：/客户：”前缀。

## 交付顺序

1. A1：持久化、数据契约、工作流、复核、汇总、API 与行为测试。
2. A2：Vue 工作台、评分卡编辑、会话/音频导入、证据回听、主管复核、团队概览。
3. A3：真实浏览器流程、旧功能回归、文档、CI 与 GitHub 推送。

## 首版不承诺

CRM/通话平台自动接入、真实销售效果、可靠的自动分离说话人、成员账号和权限、自动绩效处罚、跨客户身份解析、统计因果归因、成交概率、收费或支付系统。方案 B 保留为讨论候选，本轮不实现。
