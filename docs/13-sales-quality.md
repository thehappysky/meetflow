# 方案 A：销售会话质检与辅导（实施契约）

当前产品主次已调整：每位销售的会谈纪要为首页主线，本销售质检模块保留为辅助能力。两套数据管线暂未统一，后续需以会谈为共同来源关联纪要与质检，避免要求用户重复上传。当前新增归属/筛选和本地浏览器使用说明见 docs/14-code-map-and-demo.md 顶部补充。

目标用户是已有销售流程与录音/转写的销售主管。保留会议模块；销售工作台按项目隔离。首版是本地单用户试用版，不代表多人生产服务。

## 数据流与验收

发布不可变的阶段评分卡 → 导入会话（销售、客户、实际时间、完整性、逐段身份）→ 冻结会话与规则 → 三路专业分析 → 独立审查/最多一次定向返工 → 代码计算得分与覆盖率 → 主管复核 → 可选本地辅导任务 → 团队汇总与 Markdown 导出。

- 评分卡包含阶段、维度、权重、适用条件、达标/部分达标描述、产品依据；修改发布为新版本，旧分析不改变。
- 会话段落身份为销售/客户/未知；未知身份和不完整材料不得推断为销售未执行。
- 状态为达标/部分达标/未达标/不适用/无法判断。代码按满分/半分/零分计算，仅可评项进入分母，另展示可评覆盖率，不能把未知当零分或把缺项掩盖为满分。
- 三个专家负责需求与交易信息、流程与下一步、产品与承诺；审查者可以指出具体规则问题，定向返工一次，剩余争议转无法判断。
- 工具只读冻结快照与上游产物；每次调用前持久预留累计预算。SQLite 检查点与已完成产物支持失败恢复。真实模式无配置/失败均不转演示。
- 规则演示采用可见的字面命中词，未知默认保留，不模拟真实语义能力。真实模型接入沿用工具调用适配器，实际质量需要用户配置后验证。
- 人工复核绑定报告 hash 与会话版本，幂等保存；覆盖机器判断必须填写原因。辅导任务只在显式选择后写入现有本地看板。
- 汇总仅计已复核记录；按模式、阶段、评分卡版本和销售人员筛选。展示样本数、覆盖率、规则问题和客户信号；不生成成交率、收入或没有 CRM 依据的因果结论。
- 音频需要已有 ASR 配置。转写后先逐段确认身份，才进入评价；无自动说话人分离。文字输入支持“销售：/客户：”前缀。

## 首版不承诺

## v0.2 使用入口

1. 运行 `scripts/start.ps1`，进入左侧“销售质检”。可在顶部切换已有项目；新增项目沿用“项目资料”入口。
2. 快速体验点击“体验销售示例”。合成示例按字面词命中，不会自动宣称达标或未达标；产品资料不足为无法判断。
3. 真实使用先在“评分标准”建立阶段评分卡，填适用条件、达标/部分达标描述和已确认产品资料。发布后只追加版本，无法从旧版本覆盖最新版本。
4. “导入销售会话”填写销售、客户/商机标识、实际日期（可空），选卡对应阶段，粘贴/读取 TXT 或 MD。每行前缀为 `销售：`、`客户：`，其他前缀保留未知。文本上限 50000 字、400 段；按实际场景拆分，不静默截断。
5. 服务端有模型配置时可选真实模式。模型通过只读 `read_context` / `read_upstream` 与结构化 `submit_result` 协作。真实服务失败显示失败并支持预算内恢复，不转演示。
6. 音频使用已有 `MEETFLOW_ASR_MODEL` 配置，上传后后台转写；确认逐段身份和完整性后开始质检。支持音频定位回听。当前无自动说话人分离，逐段核对的操作成本仍需后续降低。
7. 查看得分、扣分、评价依据与覆盖率，点“核对原文”。主管可改判并填写原因；选择创建辅导任务后保存。辅导任务进入现有看板，复核幂等不会重复创建。
8. “团队概览”默认真实数据；示例须切换到规则演示。可筛选销售、评分卡版本、实际日期；日期未知的会话不进入有日期范围的筛选。按会话去重，按人员与评分卡版本分组；规则问题计数和客户信号不宣称因果关系。
9. Markdown 导出保留原机器原因、人工改判原因、模式、规则版本与冻结原文。客户信号未逐项人工审核，单独标记。

## 核心接口

全部位于 `/api/sales`，本地开发模式没有账号权限体系：

| 方法和路径 | 用途 |
|---|---|
| GET `/template` | 初始阶段评分卡 |
| GET/POST `/playbooks` | 按 project_id 查询 / 发布不可变评分卡 |
| GET/POST `/conversations` | 查询 / 导入带身份的文字会话 |
| POST `/audio` | 文件 + metadata JSON 表单，后台转写 |
| PATCH `/conversations/{id}/spans` | 乐观版本更新身份/完整性；录音原文与时间不可改写 |
| POST `/conversations/{id}/analyze` | 选择评分卡及 demo/live，冻结分析输入 |
| GET `/analyses/{id}` | 进度、来源、专家产物、机器报告和主管复核 |
| POST `/analyses/{id}/retry`、`cancel` | 预算内恢复 / 停止 |
| POST `/analyses/{id}/review` | hash + 会话版本 + 幂等键绑定主管复核 |
| GET `/analyses/{id}/export` | Markdown 报告 |
| GET `/dashboard` | 已复核会话描述统计 |

## 计分口径

达标得到该规则全部权重，部分达标得到一半，未达标为零。

`得分 = 100 × 已得权重 / 可评权重`；`覆盖率 = 100 × 可评权重 / 适用权重`。

不适用从适用分母移除；无法判断留在适用分母、移出可评分母。无可评项时得分为 null；全部不适用时覆盖率为 null。各会话得分的算术平均与样本数一起显示，不能跨评分卡版本汇总为排名。客户信号按会话去重统计，不是客户数量，且仍为自动提取。

## 验证与恢复开发

业务测试见 tests/test_sales.py；包括证据/角色隔离、规则不可变版本、材料不足降级、定向返工、失败恢复、HTTP 工具消息、累计预算、主管改判、幂等、旧版本拒绝、音频测试替身和汇总去重。它们不等于真实供应商与录音质量评测。

浏览器：运行服务后执行 `.venv/Scripts/python.exe scripts/smoke_sales_browser.py --channel msedge`，覆盖示例、证据、改判、辅导、导出、概览、发布 v2、文字导入、身份修订和 390px 布局。CI 使用 Chromium。截图保存在忽略的 test-results/sales-browser。

继续开发优先：真实授权销售样本及双人标注 → 模型/ASR 实测和错误分析 → 连接一个目标客户现有的通话或 CRM 平台 → 身份映射便利性与多人权限。
