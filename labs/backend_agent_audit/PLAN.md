# 量化审计预登记

登记日：2026-11-12（Asia/Shanghai）。必须在本批实验结果生成前保存此文件及其 SHA256。当前没有云模型配置；本机已有 Ollama Qwen2.5 7B，使用本地真实推理，不改产品默认模型，不上传用户录音。

## 实验与判定

1. 数据访问：在隔离合成数据库比较现有质检列表和 SQL 内限定公司／团队／当前中心版本、批量投影的候选。分别记录 SQL 条数、响应字节、墙钟 P50/P95、返回内容等价、公司／团队／销售权限。规模至少 10／100／500 场，每规模预热后交错运行至少 7 次。候选只有内容／权限完全一致、查询数不随行数增长、500 场中位时延降低至少 20% 才可进入产品。不得由此推出 PostgreSQL 优于 SQLite；本机 Docker daemon 不可用，跨数据库对照尚缺环境。
2. 协作：中文销售后续事项槽位小基准，公开可复核的人工编写合成案例（本轮由开发代理编写，尚无独立业务标注者，不能宣称真实客户效果）。固定输入、Schema、模型摘要、参数和日期工具结果；输出是目标后续事项的存在、负责人、截止日期、状态、条件依据和原文依据。分别比较一次调用、单 Agent 自查、两个独立专家＋证据整合审查；后一方案是候选协作协议，不冒充当前完整产品图。
3. 同一案例给相同资料、总生成预算上限和失败计入规则；多 Agent 不免费增加预算。先记录完整调用、原始输出、供应商返回 token、加载／生成时延、失败；不得将演示 Provider 的输出算真实模型效果。
4. 指标：槽位准确率、整例全对、证据集合 F1、条件依据 F1、凭空新增任务数、JSON／Schema 成功、所有案例成功率、输入／生成 token、P50/P95、重复上下文字符量。没有真实价格／电耗采样时费用／能耗为 null，不以 token 或 GPU 时间假装费用。
5. 预设准入：存在／负责人／日期／状态四个关键槽位不得比强单 Agent 基线差；全部有效案例纳入分母，失败按该例全部关键槽位错；证据 F1 不下降才讨论成本。任何关键槽位错误均不允许自动替换生产流程。本轮数据只用于开发诊断，不作独立留出验证或统计显著性结论，不能看结果后换标签、删除失败或将同义改写当独立样本扩充。
6. 资料只形成可检验假设：框架／检索／队列／存储分开比较。架构质量、执行框架开销、数据查询和 ASR 不混成一个总分。未测方案不排名；必要的权限、来源版本和并发幂等校验只在明确重复且有等价性／故障证据时删除。

## 留痕与恢复

每轮输出独立目录，不覆盖旧轮次：manifest.json（提交／脏文件摘要／环境／模型 ID／数据及计划 hash）、trace.jsonl、predictions.jsonl、failures.jsonl、metrics.json、decision.md。局部故障也落盘；运行结束与中断分别标记。运行原始数据在忽略的 test-results/backend-agent-audit，代码、合成案例和脱敏汇总可提交。

本轮先做可完成的真实本地实验和查询改进。真实中文销售标注集、其他模型、PostgreSQL／队列对照仍需后续补齐，不能由本轮小样本选出“最优总架构”。

## v2 开发诊断修订（第一轮结束后、第二轮运行前登记）

v1 完整留档，发现模型会输出 action_present=false 却同时 status=todo／done。此前提示只描述 false 的处理，没有足够明确“已完成／取消也算存在事项”的字段语义。v2 为三个方案统一补充字段定义、Schema 描述并把 Schema 放入提示；案例、gold、准入标准、生成总预算保持不变。重复次数改为 2，以观察相同参数下的重复表现。此为使用同一开发集改进协议，不是独立留出验证，不能靠 v2 成绩宣布泛化或最优架构。

## v3 单因素协议消融（运行前登记）

action_present 与 status=none 表达相同事实，却要求模型独立填写。v3 只试“移除冗余存在性字段，代码从状态派生”，保留相同 gold／生成预算／日期工具和其余槽位；只运行 one_pass、重复 2 次，与 v2 的 one_pass 配对，不能拿 v3 的简化契约和 v2 的其他架构混成公平架构对照。两轮使用同一开发集，不作选型泛化结论。

## 第二个本地模型（运行前登记）

从 Ollama 官方仓库获取适合现有 6GB 显存的 Qwen3:4b；不是根据供应商自报分数认定更优。重复 v2 契约（三方案、12案例各2次、1536总生成上限），明确 think=false，不混入思考 token 的额外预算。与 Qwen2.5 的对照只改变模型及其不支持思考／显式关闭思考的控制，不应用 v3 的字段简化。仍无独立销售标注集，不能只凭开发小样本正式上线任何模型。

## 原生接口诊断（兼容接口失败后、运行前登记）

Qwen3 兼容接口完整图返回单次最多 2139 completion tokens，超过请求中的 max_completion_tokens=512。官方兼容文档列出 max_tokens；不能假定不同兼容服务支持所有参数。新增显式 Ollama 原生 profile，以 options.num_predict=512、num_ctx=8192、think=false 及原生工具消息适配运行一次完整图；保留18次／180秒预算，不放宽校验，不改产品 .env 或默认 profile。记录每次实际用量和最终成功／失败。此处同时改变接口和思考设置，只是集成修复验证，不能当单因素模型／架构质量对照。

原生动态协调诊断仍在6步内未提交计划。下一次只把协调者换为此前已登记的固定代码DAG，原生 profile、模型、512／18次／180秒预算不变；仍然只作故障定位，不从单例成功／失败推断质量排名。

## 用户固定多Agent方向后的内部设计对照（运行前追加）

最终产品必须多Agent协作，单Agent仅实验参照，不再列为交付候选。旧结果／标签不改，不强行宣称多Agent优于单Agent。

新增拓扑开发诊断，固定Qwen3:4b、v2输入与gold、角色说明／Schema／原生接口、think=false、每调用512上限、最多3调用1536总上限、num_ctx4096、temperature0、按角色／重复固定seed，12场景各重复2次，随机交错三方案：A串行交接（本次证据→历史状态→证据审查）；B独立双专家→必经审查；C独立双专家→仅在有效产物不完全一致或有验证错误时审查。C至少运行两个独立Agent，绝不是单Agent路径。全部读取相同冻结资料，只有交接依赖和审查门控不同；本机单GPU将逻辑独立调用串行执行，不推断云端并行耗时。

统一输出校验：Schema、真实片段ID、存在性／状态一致、none时负责人／日期为空。中间无效产物原样留痕交审查，不提前丢弃整例；最终无效才记失败，三方案适用同规则。门控不读gold、不用自报置信度；按全部六类字段（两个引用集合忽略顺序）比较。无审查采用共识也要评估同错率，不能把共识当正确。

统计四槽位全对、含证据条件全对、支持／条件F1、凭空任务、完成率、调用与实际token、P50/P95、审查触发率、相对状态专家的错变对／对变错，以及未审查共识的错误数。比较有效完成只是流程指标，不能替代质量。仅质量不低于B且无新增严重错误时，才讨论C节省；若取舍不清或都未过既有业务门槛，则不选生产赢家。此为同12例开发集的拓扑诊断，不能当完整产品、独立留出验证、质检效果或框架性能比较。保存每轮精确源码／计划／数据／模型摘要和所有请求、无效中间产物、失败及逐例结果。
